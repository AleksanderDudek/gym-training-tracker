# Meal prep — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> Executed inline in the planning session (the user is away and asked for an autonomous finish).

**Goal:** A plan for the next 5–14 days for one person: meals that meet the profile's goal, cooked
ahead in blocks of at most 4 days, bought in one physical shop (plus at most one online shop), with a
shopping list per shop, followed along in the diary, and a check-in that corrects the calorie goal
from the weigh-ins and the log.

**Architecture:** Spec: `docs/superpowers/specs/2026-10-20-meal-prep-design.md`. Pure planning in
`src/food/prep/` (candidates → selection → portions → shopping → snapshot); the snapshot is a row of
a new Dexie table `prep` (DB v4), so the plan and its list render without the product base. Screens
in `src/food/components/prep/` (`fd-prep-`): a section on top of the plan page, the list page
`#/jedzenie/zakupy`, and a diary card. The profile gains maintenance and gain paces.

**Tech Stack:** React 19, TypeScript 6, Dexie 4, Vitest 5 + jsdom + fake-indexeddb.

## Tasks

### Task 1: Goal direction (diet)
- [ ] `energy.ts`: `goalDirection` (±0.5 kg is keeping), `dayReaching` with a direction; tests.
- [ ] `DietProfilePage`: paces −1…−0.25, utrzymanie, +0,25; warnings by direction (surplus only
  against a loss goal, deficit against a gain goal, gain faster than 0.5 % of weight a week); reach
  date by direction, „utrzymanie wagi” for keeping.
- [ ] `DietProgressPage`: reach dates and „Do celu” by direction.
- [ ] Tests: energy, profile page chips and warnings, progress tile for a gain goal.

### Task 2: Foundations of `prep/`
- [ ] `types.ts`, `slots.ts` (3/4/5 tables, shares sum to 1), `blocks.ts` (balanced blocks of ≤ 4
  days), `aisles.ts` (every ingredient id → aisle; order and labels), `sides.ts` (catalog, labels,
  macros from the physical shop's product or typical), `format.ts` (`portionLabel`, `dayRange`).
- [ ] Export `random` from `diet/suggest.ts`.
- [ ] Tests: blocks (5, 7, 10, 14), slots, every ingredient has an aisle, side labels, portion labels.

### Task 3: Candidates and selection
- [ ] `candidates.ts`: `planRecipes` (basket rule via `resolveRecipe`, exclusions by ingredient
  groups, fit ≠ avoid; flags batch, fixed, starch, savoury; non-pantry ingredients).
- [ ] `select.ts`: role filters, score (fit, density, size, quick, favourite, overlap), seeded pick
  of the four best, rotation counts, distinct boxes per block, no recipe in two roles while others
  exist; `missing` roles; `swapCandidate`.
- [ ] Tests on a synthetic index (store ingredients in Biedronka, online ones in Myprotein).

### Task 4: Portions and sides
- [ ] `portions.ts`: variables (box-shared or per meal), day score, coordinate descent with single
  and paired moves, fixed portions, side caps.
- [ ] Tests: every style × meal count × cooking mode on the catalog: energy ±7 %, protein ≥ min,
  keto/low-carb carbs ≤ limit (+5 %); equal boxes; gotowce at 1; deterministic.

### Task 5: Targets and check-in
- [ ] `targets.ts`: weekly balance spread once over the plan's days of the current week.
- [ ] `checkin.ts`: regression, logged share, plausibility, correction, cap, floor, goal reached.
- [ ] Tests for each status and limit.

### Task 6: Shopping list
- [ ] `shopping.ts`: uses (boxes and fresh meals) + sides → per ingredient; product and shop from the
  resolved recipe; groups, aisles, packs (`packSize`, 5 % tolerance), pieces, prices (per kg, online
  offer), freezing for raw meat and fish from day 3; `shoppingText`.
- [ ] Tests.

### Task 7: Generate and swap

- [ ] Tests; `scripts/food/check-prep.ts` + `npm run food:check-prep` on the real data.
