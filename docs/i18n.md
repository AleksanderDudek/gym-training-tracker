# Languages (i18n)

The app speaks Polish and English. This is how text is written so both stay complete.

## How the language is chosen

`src/i18n.ts`, once per page load:

1. the choice saved in Settings → „Język · Language” (`localStorage['kb-lang']`);
2. otherwise the first supported language in `navigator.languages` (`pl-PL` → Polish);
3. otherwise English (a German browser reads English more easily than Polish).

Changing the language saves the choice and reloads the page. The language is constant for a visit,
so engine modules and module-level constants can hold translated text without hooks or context.
`document.documentElement.lang` follows it (`main.tsx`).

`LOCALE` is `pl-PL` or `en-GB` (metric, day–month dates, weeks from Monday, like the app). Every
`Intl.*` and `toLocaleString` call uses `LOCALE`, never a hard-coded `'pl-PL'`.

## Writing text

**A catalog per screen or module** — both languages side by side, the English half typed by the
Polish one (a missing key, an extra key or a different function signature does not compile):

```ts
import { pluralEn, text } from '../i18n';
import { plural } from '../engine/quips';

const T = text({
  pl: {
    save: 'Zapisz',
    left: (n: number) => `${n} ${plural(n, ['krok', 'kroki', 'kroków'])} do celu`,
  },
  en: {
    save: 'Save',
    left: (n: number) => `${n} ${pluralEn(n, 'step', 'steps')} to go`,
  },
});
// …
<button>{T.save}</button>
```

- A catalog that holds JSX (a paragraph with `<b>`) lives in a `.tsx` file; values are `ReactNode`.
- Small catalogs sit at the top of the file that uses them; big ones go to a sibling `Foo.text.tsx`.
- **Data** (exercise names, recipe titles, jokes) uses `say(pl, en)` right in the data:
  `name: say('Przysiad ze sztangą', 'Barbell back squat')`. The data keeps its `string` type.
- Polish plurals use the existing helpers (`plural` in `engine/quips.ts`, `food/lib/format.ts`);
  English uses `pluralEn(n, one, other)`.
- Numbers: `num(n, digits)` from `i18n.ts`, or `toLocaleString(LOCALE, …)`.

**Never translate stored values or keys.** A Polish string that is saved (a meal slot in the diary,
a group name used in logic, a route like `#/ustawienia`, a product name, a store name) stays as it is;
show a translated label for it instead. Before translating a field, look for every place that
compares, stores or looks it up.

Kept in Polish on purpose: product names and restaurant menu items (the Polish market's own names),
store and chain names, routes, the backup file format, the companion app's name „GYM TRACKER
Zdrowie”. A literal like that is marked with `// i18n-ignore: <reason>` on its line or the line above.

## Checking

- `node scripts/i18n-scan.mjs [paths]` lists Polish text outside catalogs (`--count` for totals).
- Tests run in Polish (`src/test/setup.ts`). A test file that runs in English starts with
  `vi.hoisted(() => { globalThis.__KB_LANG__ = 'en'; })` before its imports — each area has an
  English smoke test that renders its screens and finds no Polish letters.
